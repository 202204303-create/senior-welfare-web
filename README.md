## 1. 프로젝트 목적

### 해결하려는 문제

- 혼자 사는 어르신은 약을 거르거나 몸이 안 좋아도 **스스로 알리기 어렵습니다.**
- 보호자는 매번 전화로 확인해야 하고, 연락이 닿지 않으면 **불안한 채로 기다립니다.**
- 복지사는 담당 어르신이 많아 **누구부터 챙겨야 하는지** 판단하기 어렵습니다.

### 목표

어르신이 버튼 한 번으로 "오늘 괜찮다"를 남기면, **보호자는 바로 확인하고, 이상이 생기면 보호자와 복지사에게 알림이 갑니다.** 어르신에게는 쉽고, 보호자에게는 안심되고, 복지사에게는 우선순위가 보이는 서비스를 만듭니다.

### 범위

- 교수님 피드백에 따라 **안부·복약 확인 핵심 기능에만 집중**합니다. (일자리·시설 지도·복지 혜택 화면은 11/24에 뺐습니다)
- 카카오톡·문자 알림은 외부 발송 업체가 필요해 **준비 중**입니다. 소셜 로그인(카카오·네이버)은 쓰지 않고 계정 로그인으로 갑니다.

### 세 사용자의 목적

| 사용자 | 핵심 질문                                   | 주요 행동                           | 화면 정보량 |
| ------ | ------------------------------------------- | ----------------------------------- | ----------- |
| 어르신 | "오늘 뭘 해야 하지?"                        | 일어났어요, 약 체크, 긴급 요청      | 매우 적게   |
| 보호자 | "오늘 괜찮은가? 지금 연락해야 하나?"        | 상태 확인, 이상 알림 확인, 전화     | 중간        |
| 복지사 | "오늘 누구를 먼저 챙기고, 무엇을 처리했나?" | 우선순위 확인, 빠른 처리, 상담 기록 | 많게        |

## 2. 사용자별 프론트엔드 기획

> 어르신·보호자는 현재 동작합니다. 복지사는 **시연용 1명 화면만** 있고, 아래 복지사 설계는 앞으로 만들 내용으로 **팀 합의 전**입니다. 화면 그림과 세부 규칙은 [`docs/role-interfaces.md`](docs/role-interfaces.md)에 있습니다.

### 공통 원칙

- **한 가지 데이터, 세 가지 화면**: 데이터는 Firestore `families/{코드}`에 한 번만 저장하고, 화면은 역할마다 따로 만듭니다. 공통 로직은 `features/care/`에 둡니다.
- **시니어 친화**: 큰 글씨(기본 18px, 3단계), 48px 이상 터치 영역, 색만으로 구분하지 않고 글자·아이콘을 함께 사용, 아이콘 버튼에는 `aria-label`, 로딩·오류·빈 결과 화면을 항상 함께 제공
- **상태 표현**: 복용함 / 예정 / 지금 / 놓침 (`getMedStatus`, `STATUS_STYLE` 공유)
- 역할이 맞지 않는 주소로 가면 `homePathOf(role)`로 보냅니다.

### 2.1 어르신 — 할 일을 한 번에 하나, 메뉴는 최소로

| 화면    | 경로      | 내용                                                                                 |
| ------- | --------- | ------------------------------------------------------------------------------------ |
| 홈      | `/`       | 첫 설정, "일어났어요", 오늘의 약("먹었어요"), 긴급 도움 요청, 사용 안내              |
| 약      | `/care`   | 약 추가·고치기·삭제, 약 시간 설정                                                    |
| 알림    | `/alerts` | 보호자 연결 링크·코드, 휴대폰 알림·기상 확인 시간·음성 안내, 보낸 알림과 보호자 확인 |
| 내 정보 | `/my`     | 이름·보호자 정보, 글자 크기, 음성 안내                                               |

- **현재**: 기상 확인, 복약 체크·취소(누른 약은 4초간 '잘 드셨어요' 뒤 아래로), 약 목록을 **현재 시각 기준**으로 정렬(지금·다가오는 약 → 놓친 약 → 드신 약), **큰 시계**(오늘의 약 바로 위), 약 관리, 첫 설정 카드, 화면·음성·휴대폰 알림 안내, SOS(확인 창 → 보낸 뒤 '알렸어요' 화면, 119 안내), 보호자에게 링크 보내기 ✅
- 흐름: 버튼 → 화면에 즉시 반영 → 서버 저장 → 보호자 휴대폰 알림. 저장 실패 시 "다시 시도".
- 보호자·복지사가 알림을 확인한 것은 어르신께 다시 알리지 않습니다. **긴급 요청(SOS)만** 보호자가 확인하면 긴급 버튼 아래에 소리·알림 없이 조용히 표시합니다. 어르신에게 가는 휴대폰 알림은 약 시간·기상 확인 시간 안내뿐입니다.
- **남은 작업**: 요일별 복용 · 약마다 놓침 기준 · 아이폰 '홈 화면에 추가' 그림 안내

### 2.2 보호자 — 첫 화면에서 "오늘 괜찮은가?"에 바로 답

| 영역      | 내용                                                       |
| --------- | ---------------------------------------------------------- |
| 상단 요약 | "오늘 괜찮아요" 또는 "확인 필요"                           |
| 이상 카드 | 미확인 기상·놓친 약·긴급 요청. 카드마다 "확인했어요", 전화 |
| 오늘 기록 | 기상 시각, 복약 체크 목록, 어르신 앱 마지막 사용 시각      |
| 최근 기록 | 최근 7일                                                   |
| 설정      | 휴대폰 알림 허용, 가족 코드                                |

- **현재**(`/guardian`): 링크·코드·계정으로 연결, **어르신 최대 4명**(위쪽 이름 버튼으로 전환, 이름마다 확인할 일 숫자, 다른 어르신을 보고 있어도 새 알림을 이름과 함께), 실시간 구독, 미확인 직접 판단(`findCareIssues`), "확인했어요"(`ackAlert`), 확인한 알림 **지우기**(하나씩·모두, 다시 보기), **아침 안부 알림 받기** 스위치(기본 꺼짐), 어르신 전화(`tel:`), 휴대폰 알림 허용·상태 안내 ✅
- 알림: **문제가 있을 때만** 휴대폰으로 옵니다(긴급 요청, 기상 확인 없음, 약 놓침). '일어났어요'·'먹었어요' 같은 좋은 소식은 화면에만 보이고, '아침 안부 알림 받기'를 켠 기기에만 '일어나셨어요'가 조용히 갑니다. 30분 동안 확인하지 않으면 복지사에게 넘어갑니다. ([알림 정책](#알림-정책-교수님-피드백-반영))
- **남은 작업**: 계정 로그인 모드의 보안 규칙을 '보호자 1명 = 어르신 최대 4명'으로 바꾸기(지금 규칙은 1명) · 푸시가 꺼져 있으면 상단 경고

### 2.3 복지사 — 수십 명을 담당해도 "누구를 먼저, 어떻게 빨리"

**현재**(`/worker`): **PC 우선 전자차트형 3단 업무 화면**입니다. 왼쪽 오늘 큐 표(등급 → 기다린 시간, 정상 어르신은 아래), 가운데 어르신 차트(고정 헤더 · 📌 특이사항 · 타임라인/개요/복약/상담 기록/특이사항 탭), 오른쪽 처리 패널(결과 5종 · 메모 템플릿 · 다음 행동 · 다음 일정 · 저장, 5초 되돌리기). 단축키 `J`/`K` 이동, `/` 검색, `E`·`N`·`V`·`G`·`O` 결과, `Ctrl+Enter` 저장, `?` 도움말. 어르신·보호자 화면과 달리 글자 13~15px의 촘촘한 화면이고, 휴대폰에서는 목록 → 차트 → 처리로 한 칸씩 넘깁니다. ✅ 에뮬레이터에서 저장·되돌리기까지 확인

**설계**: 복지사의 하루는 `출근 → 오늘 큐에서 긴급·미확인 처리 → 통화·방문 → 기록 작성 → 명단 점검 → 퇴근 전 미처리 점검` 입니다.

**① 오늘 큐 (홈)** — 명단이 아니라 **처리할 일의 줄**입니다. 같은 어르신의 이슈는 한 카드로 묶고, "왜 여기 있나?" 칩(긴급 요청, 보호자 미확인 25분, 독거 등)을 붙입니다. 정렬은 등급 높은 순 → 오래 기다린 순입니다.

| 등급            | 조건                                   | 표시                  | 기대 처리 시간 |
| --------------- | -------------------------------------- | --------------------- | -------------- |
| P1 긴급         | 어르신이 긴급 요청을 누름              | 빨강 "긴급"           | 즉시(5분)      |
| P2 에스컬레이션 | 보호자가 N분(예: 30분) 동안 확인 안 함 | 주황 "보호자 미확인"  | 1시간          |
| P3 기상 미확인  | 기준 시각(예: 10시)이 지나도 기상 없음 | 주황 "기상 미확인"    | 당일 오전      |
| P4 복약 반복    | 같은 약을 2회 이상 연속 놓침           | 노랑 "복약 누락 반복" | 당일           |
| P5 연락 공백    | 마지막 처리 후 N일(예: 3일) 경과       | 파랑 "연락 필요"      | 이번 주        |
| P6 예정         | 오늘 방문·통화 일정                    | 회색 "오늘 예정"      | 일정 시각      |
| P7 정상         | 이슈 없음                              | 초록 "정상"           | 목록에서만     |

**② 빠른 처리** — 한 번 누르면 결과가 기록되고(5초 동안 "되돌리기"), 메모는 선택입니다.

| 결과 버튼        | 기록 값             | 처리 후                     |
| ---------------- | ------------------- | --------------------------- |
| 통화 · 이상 없음 | `call_ok`           | 이슈 종결                   |
| 통화 · 받지 않음 | `call_no_answer`    | 이슈 유지, 재시도 시각 설정 |
| 방문 필요        | `visit_needed`      | 방문 일정 칸 열림           |
| 보호자에게 전달  | `guardian_notified` | 이슈 유지, 보호자 응답 대기 |
| 기타             | `other`             | 메모 필수                   |

전화는 어르신·보호자 둘 다 한 탭, 통화 후 돌아오면 결과 기록 시트가 뜨고, 자주 쓰는 문장은 템플릿 칩으로 제공합니다. **일괄 처리는 정상 건만** 가능하며 이슈가 있는 사람은 한 건씩 결과를 남깁니다.

**③ 어르신별 차트** — 고정 헤더(이름·나이·상태·마지막 연락·전화·📌 특이사항) 아래 탭 5개입니다.

| 탭        | 내용                                                                            |
| --------- | ------------------------------------------------------------------------------- |
| 개요      | 이번 주 기상·복약 준수율, 처리 건수, 마지막 통화                                |
| 타임라인  | 알림·기상·복약·처리 기록을 시간순으로 합친 목록                                 |
| 복약      | 약 목록, 최근 14일 복용 표                                                      |
| 상담 기록 | 템플릿·메모·다음 행동·다음 일정. **저장 후 수정 불가**, 정정은 새 기록으로 추가 |
| 특이사항  | 고정 메모(의료·생활·연락), 📌 항목은 모든 탭 헤더에 표시                        |

**④ 오늘 관리 대상 · 전체 명단** — 열린 이슈, 오늘 일정, N일 이상 연락 없음, 위험·관찰 상태, "오늘 챙기기" 고정 중 하나라도 해당하면 오늘 목록에 자동 포함합니다. 명단은 상태·마지막 통화·오늘 기상·오늘 복약·열린 이슈·다음 일정을 한 줄로 보여 주고, 퇴근 전에 남은 항목을 체크리스트로 보여 줍니다.

## 3. 백엔드 구현 계획

별도 서버 없이 **Firebase(Firestore·FCM) + Vercel 서버 함수 + GitHub Actions**로 구성합니다. 모두 무료 구성입니다.

### 3.1 이미 구현된 것

### 3.3 데이터 구조

```
families/{code}                          어르신 한 명 (이름·보호자·약 목록·알림 기준·마지막 사용)   ✅ 현재
  ├─ days/{YYYY-MM-DD}                   그날의 기상 시각·복용 기록                                   ✅ 현재
  ├─ alerts/{id}                         알림 기록 (+ 보호자 확인 ackAt/ackBy)                        ✅ 현재
  ├─ pushTokens/{hash}                   알림 받을 기기 (token, role, morning=아침 안부 받기)                                 ✅ 현재
  ├─ checkinPushes/{key}                 아침 안부 알림을 보낸 표시 (중복 방지)                  ✅ 현재
  ├─ summary/current                     서버가 갱신하는 요약 (복지사 큐·명단이 이것만 읽음)           ✅ 현재
  ├─ actions/{id}                        복지사 처리·상담 기록 (추가만 가능)                          ✅ 현재
  └─ notes/{id}                          특이사항 고정 메모                                           ✅ 현재
users/{uid}                              역할(role)과 연결된 가족 코드                                ✅ 코드 (계정 로그인 모드)
workers/{uid}/assignments/{code}         복지사 담당 배정 (이름·동·태그·오늘 챙기기)                  ✅ 코드 (계정 로그인 모드)
```

- 가족 수가 늘면 10분 주기 확인의 읽기 횟수도 늘어납니다. 가족 1곳당 약 5번을 읽으므로 Firebase 무료 한도(하루 5만 읽기)로는 **약 70가족**까지가 한계입니다. 그 이상이면 담당 배정된 가족만 확인하도록 바꿉니다.
- 명단·큐는 **summary만** 구독하고, 과거 기록은 그 어르신을 열었을 때만 가져옵니다. (담당 50명을 모두 실시간 구독하면 읽기 비용이 커짐)
- Firestore `in` 조건은 한 번에 30개까지라서, 담당이 많으면 나눠서 읽습니다. (실제 담당 상한은 확인 필요)

### 3.4 권한과 알림 정책

| 대상   | 읽기             | 쓰기                                            |
| ------ | ---------------- | ----------------------------------------------- |
| 어르신 | 자기 가족 문서   | 자기 날짜 기록, 알림 생성                       |
| 보호자 | 연결된 가족 문서 | 알림 확인(`ackBy`), 가족 정보 일부              |
| 복지사 | 배정된 가족 문서 | 알림 확인, 처리·상담 기록 추가 (수정·삭제 불가) |

알림을 누가, 언제, 어떻게 받는지는 아래 [알림 정책](#알림-정책-교수님-피드백-반영)에 정리했습니다.

### 알림 정책 (교수님 피드백 반영)

원칙: **문제가 있을 때만 울린다.** 좋은 소식까지 매번 울리면 보호자가 알림에 무뎌져 정작 중요한 알림을 놓칩니다. 보호자는 어르신 1~4명, 복지사는 수십 명을 돌볼 수 있으므로 **알림 제목에 어르신 이름**을 붙여 구분합니다.

| 단계               | 상황                                 | 받는 사람                                                | 휴대폰 알림                                                                   |
| ------------------ | ------------------------------------ | -------------------------------------------------------- | ----------------------------------------------------------------------------- |
| 🚨 긴급            | 어르신 긴급 요청(SOS)                | 보호자 + 복지사 **동시에**                               | `🚨 늘봄 긴급 · 이름 님`, 길고 강한 진동, 직접 닫을 때까지 남음               |
| ⚠️ 확인 필요       | 기상 확인 없음, 약 놓침              | 보호자                                                   | `⚠️ 늘봄 확인 필요 · 이름 님`, 보통 진동                                      |
| ⚠️ 확인 필요       | 보호자가 **30분** 동안 확인하지 않음 | 복지사                                                   | `⚠️ 늘봄 보호자 미확인 · 이름 님`                                             |
| ☀️ 소식 (선택)     | '일어났어요'                         | '아침 안부 알림 받기'를 켠 보호자 기기만 (**기본 꺼짐**) | `☀️ 늘봄 안부 · 이름 님`, 소리·진동 없음                                      |
| 알림 없음          | '먹었어요'                           | —                                                        | 보호자 화면에만 실시간 표시 (서버에서도 보내지 않음)                          |
| 어르신 안내        | 약 드실 시간, 기상 확인 마감 30분 전 | 어르신                                                   | 화면 위 안내(누를 때까지 남음) + 휴대폰 알림 + 음성 안내(켠 경우)             |
| 어르신께 확인 표시 | 보호자가 확인함                      | 어르신                                                   | 일상 알림은 표시 안 함. **SOS만** 긴급 버튼 아래에 조용히 '○○님이 확인했어요' |

- 진동 차이는 안드로이드에서만 동작합니다. 아이폰은 제목의 🚨/⚠️/☀️ 로 구분합니다.
- 보호자가 여러 명이면 알림을 켠 **모든 보호자 기기**로 갑니다. 아침 안부는 기기마다·어르신마다 따로 켭니다.
- 보호자는 확인한 알림을 '지우기'로 자기 화면에서 지울 수 있습니다. 기록은 남아(복지사 확인·에스컬레이션에 필요) 다른 사람 화면에는 영향이 없습니다. 확인 전 알림은 지울 수 없습니다.

2. PR을 올릴 때 이 README의 **작업 기록** 표 맨 아래에 한 줄을 같이 추가합니다.
   ```
   | 11/20 | 내 GitHub 아이디 (이름) | 한 일을 한 문장으로 | #7 |
   ```
   - 날짜는 `월/일`, PR 번호는 PR을 만든 뒤 알 수 있으니 처음엔 `-`로 두고 나중에 고쳐도 됩니다.
   - 문서·발표 자료처럼 코드가 아닌 일도 적습니다.
3. **남은 할 일**에서 끝난 항목은 `- [ ]`를 `- [x]`로 바꾸고, 맡을 일에는 `담당:` 뒤에 이름을 적습니다.
4. 새로 생긴 할 일은 해당 기한 아래에 `- [ ] 할 일 — 담당:` 형식으로 추가합니다.
5. 수업 일정의 상태는 ✅ 완료 / 🔄 진행 중 / ⬜ 예정 중 하나로 바꿉니다.

## 5. 팀이 정할 것과 완료 기준

**복지사**: ① 한 명이 담당하는 어르신 수 상한(30명? 50명?) ② 연락 공백 기준(예: 3일) ③ 에스컬레이션 대기 시간(예: 30분) ④ 인수인계(휴가·담당 변경) ⑤ 방문 일정을 앱 안에서만 관리할지 외부 캘린더와 연동할지 ⑥ 복지사 화면을 데스크톱 우선으로 할지 모바일 우선으로 할지

**공통**: ⑦ ~~긴급 요청을 보호자와 복지사에게 동시에 보낼지 순서대로 보낼지~~ → **동시에** (11/26) ⑧ ~~보호자가 여러 명이면 모두에게 보낼지 대표에게만 보낼지~~ → **알림을 켠 모든 보호자 기기** (11/26) ⑨ 처리·상담 기록 보관 기간(개인정보 보관 기간과 함께) ⑩ 보호자 연락처를 어르신이 직접 바꿀 수 있는지, 복지사만 바꿀 수 있는지

**완료 기준**

- [ ] 세 역할이 로그인 후 각자의 첫 화면으로 이동한다 (시연용 계정으로는 현재 가능)
- [ ] 역할이 맞지 않는 주소로 접근하면 막히고 안내가 나온다
- [ ] 보호자는 자기 가족 기록만 본다 (규칙 테스트로 확인)
- [ ] 복지사는 배정된 가족만 보고, 처리 기록은 수정·삭제할 수 없다
- [ ] 복지사 오늘 큐가 우선순위 규칙대로 정렬된다 (테스트 케이스 포함)
- [ ] 원탭 처리 후 3초 안에 카드 상태가 바뀐다
- [ ] 차트 화면에서 과거 7일 기록이 타임라인에 시간순으로 보인다
- [ ] 알림이 보호자와 복지사에게 앱이 닫혀 있어도 도착한다
- [ ] 세 화면 모두 로딩·오류·빈 결과 상태가 있다
- [ ] 어르신 화면이 접근성 체크리스트(기본 글자 18px 이상, 터치 영역 48px 이상, 아이콘 버튼 `aria-label`, 긴급 버튼 홈 고정)를 통과한다


`.env.example` 을 `.env` 로 복사해 필요한 값만 넣습니다. 모두 비워 두어도 동작합니다.

| 변수                      | 용도                                                                                                                        | 비워 두면                                  |
| ------------------------- | --------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| `VITE_FIREBASE_*`         | 다른 Firebase 프로젝트를 쓸 때 (휴대폰 알림에는 `VITE_FIREBASE_MESSAGING_SENDER_ID` 도 필요)                                | 팀 프로젝트(`neulbom-c7096`)               |
| `VITE_FIREBASE_DISABLED`  | `true` 면 서버 없이 기기에만 저장                                                                                           | 서버 저장 사용                             |
| `VITE_FIREBASE_VAPID_KEY` | 웹 푸시 공개 키 (코드의 `TEAM_VAPID_KEY` 대신)                                                                              | 앱이 열려 있을 때만 휴대폰 알림            |
| `VITE_AUTH_MODE`          | `firebase` 로 두면 Firebase 이메일 로그인 (켜기 전에 [계정 로그인으로 전환하기](#계정-로그인으로-전환하기) 순서를 따르세요) | 시연용 계정 (앱 코드 안의 아이디·비밀번호) |

서버(Vercel 환경 변수, **비밀값**): `FIREBASE_SERVICE_ACCOUNT`(서비스 계정 키 JSON), `CRON_SECRET`(임의의 긴 문자열). GitHub 저장소 비밀값: `CRON_SECRET`(같은 값).

**배포**: `main` 에 PR 을 합치면 Vercel 이 자동으로 배포하고, PR 마다 미리보기 주소도 만들어집니다. `vercel.json` 에 SPA 라우팅 설정이 있고, 연결 정보 폴더 `.vercel` 은 Git 에 올리지 않습니다.

## 8. 사용·운영 가이드

### 가족 연결 방법

1. 어르신 기기의 `알림` 화면에 6자리 **보호자 연결 코드**가 나옵니다.
2. **"보호자에게 링크 보내기"** 를 누르면 링크를 누르는 것만으로 보호자가 연결됩니다. (코드를 직접 입력해도 됩니다.)
3. 보호자는 `/guardian` 에서 오늘의 기상·복약, 알림, 최근 7일 기록을 실시간으로 봅니다.
4. 어르신이 여러 명이면 보호자 화면 위쪽 **'어르신 추가'** 로 최대 4명까지 등록하고, 이름 버튼으로 바꿔 가며 봅니다. 다른 어르신 링크를 눌러도 목록에 추가됩니다.

### 시연용 계정

로그인 화면에서 아이디·비밀번호를 입력하거나, 아래 "시연용 계정"을 눌러 채웁니다. 세 계정은 **같은 가족 코드(`NEULBM`)** 를 써서 한 어르신의 기록을 함께 봅니다.

| 계정           | 아이디 / 비밀번호   | 로그인 후   | 할 수 있는 일                                                                                                                 |
| -------------- | ------------------- | ----------- | ----------------------------------------------------------------------------------------------------------------------------- |
| 사용자(어르신) | `senior` / `1234`   | `/` (홈)    | 기상 확인, 복약 체크, 긴급 요청                                                                                               |
| 보호자         | `guardian` / `1234` | `/guardian` | 가족 코드 입력 없이 어르신 상태 실시간 확인, '확인했어요', 확인한 알림 지우기, 아침 안부 알림 켜기, **어르신 추가(최대 4명)** |
| 복지사         | `worker` / `1234`   | `/worker`   | 오늘 큐(등급 순)·어르신 차트·처리 기록(전자차트형 3단). 시연용 모드에서는 시연 가족(`NEULBM`) 1명                             |

- **시연 순서 예시**: 폰 A에서 `senior` 로그인 → "일어났어요" 누르기 → 폰 B에서 `guardian` 로그인(또는 PC에서 `worker`) → 기상 확인이 바로 보임 → 폰 A에서 긴급 요청 → 보호자·복지사 화면에 표시.
- **보안이 아닙니다.** 아이디와 비밀번호가 앱 코드(`src/features/auth/lib/demoAccounts.ts`)에 그대로 들어 있어 누구나 볼 수 있습니다. 서버(Firestore)도 여전히 가족 코드를 아는 사람이면 접근됩니다. 시연용이며, 실제 서비스 전에는 Firebase 이메일 로그인과 역할별 보안 규칙으로 바꿔야 합니다.
- `처음 시작하기 (가입 없이)`는 예전처럼 사용자 화면을 열고 기기마다 다른 가족 코드를 씁니다.
- 복지사 화면의 담당 어르신 목록은 코드(`WORKER_FAMILY_CODES`)에 고정되어 있습니다.

### 계정 로그인으로 전환하기

지금은 **시연용 계정**(앱 코드 안의 아이디·비밀번호)으로 동작합니다. 실제 계정 로그인과 역할별 보안 규칙으로 바꾸는 순서입니다. **순서를 지켜야 합니다.** 규칙을 먼저 게시하면 기존 사용자가 모두 막힙니다.

| 순서 | 할 일                                                                                           | 누가                       |
| ---- | ----------------------------------------------------------------------------------------------- | -------------------------- |
| 1    | Firebase 콘솔 → Authentication → 로그인 방법 → **이메일/비밀번호** 사용 설정                    | 사람 (콘솔)                |
| 2    | 내 컴퓨터에서 `node scripts/seed-accounts.mjs` 로 계정 3개와 역할·담당 배정 만들기 (아래 설명)  | 사람 (서비스 계정 키 필요) |
| 3    | Vercel 환경 변수 `VITE_AUTH_MODE` = `firebase` 추가 → **Redeploy**                              | 사람 (Vercel)              |
| 4    | 배포 주소에서 세 계정으로 로그인해 확인 (어르신은 기록, 보호자·복지사는 화면에 기록이 보이는지) | 사람                       |
| 5    | Firebase 콘솔 → Firestore → 규칙에 **`firestore.roles.rules` 내용을 붙여 넣고 게시**            | 사람 (콘솔)                |
| 6    | 다시 세 계정으로 로그인해 확인. 문제가 있으면 아래 되돌리기                                     | 사람                       |

**2번 — 계정 만들기** (PowerShell 예시. 비밀번호는 6자 이상이고 `1234`는 쓸 수 없습니다. 실제로 쓰는 비밀번호는 쓰지 마세요)

```powershell
$env:GOOGLE_APPLICATION_CREDENTIALS = "C:\경로\서비스계정키.json"
$env:NEULBOM_PASSWORD_SENIOR   = "정한 비밀번호"
$env:NEULBOM_PASSWORD_GUARDIAN = "정한 비밀번호"
$env:NEULBOM_PASSWORD_WORKER   = "정한 비밀번호"
node scripts/seed-accounts.mjs
```

- 아이디는 `senior`, `guardian`, `worker` 이고, 내부적으로 `아이디@neulbom.app` 이메일로 만들어집니다. 여러 번 실행해도 안전하고, 다시 실행하면 비밀번호가 바뀝니다.
- `users/{uid}` 에 역할과 가족 코드(`NEULBM`)가 저장되고, 복지사 계정에 이 어르신이 담당으로 배정됩니다.
- 서비스 계정 키 파일은 끝나면 지우세요. 프로젝트 폴더나 Git 에 두지 않습니다.

**전환 후 달라지는 점**

- 로그인 화면에 시연용 계정 목록과 "처음 시작하기 (가입 없이)"가 사라집니다.
- 보호자는 **링크·가족 코드로 들어갈 수 없고**, 보호자 계정으로 로그인해야 합니다.
- 서버는 익명 로그인을 받지 않고, 역할별로 읽고 쓰는 범위가 나뉩니다. (어르신: 자기 가족 기록 쓰기 / 보호자: 읽기와 알림 확인 / 복지사: 배정된 가족 읽기, 알림 확인, 처리 기록 추가)
- 규칙은 `npm run test:rules` 로 실제 에뮬레이터에서 시험합니다. (20개)

**되돌리기**: Vercel 에서 `VITE_AUTH_MODE` 를 지우고 Redeploy, 규칙은 `firestore.rules` 내용을 다시 게시하면 시연용 계정 방식으로 돌아갑니다.

### 약 종류와 복용 시간 설정

`약` 화면에서 어르신(또는 가족)이 약마다 직접 설정합니다. 매일의 복용 체크는 `홈`에서 합니다.

| 하고 싶은 일 | 방법                                  |
| ------------ | ------------------------------------- |
| 약 추가      | **약 추가하기** 버튼                  |
| 약 수정      | 약 옆의 **고치기**                    |
| 약 삭제      | 약 옆의 **삭제** (확인 창이 한 번 뜸) |

입력 항목: **약 이름**, **복용 시간대**(아침·점심·저녁·취침 전, 고르면 알림 시각이 기본값으로 채워짐), **알림 시각**(원하는 시각으로 직접 변경), **메모**(선택, 예: 식후 30분).
같은 화면에서 **기상 확인 마감 시간**(기본 10:00)도 바꿀 수 있습니다.

- 약 목록은 서버에 저장되어 보호자 화면에도 같이 보입니다. 약은 어르신 쪽에서만 바꿀 수 있고, 보호자 화면에서는 볼 수만 있습니다.
- 오늘 알림 시각이 이미 지난 뒤에 추가·변경한 약은 **"내일부터"** 로 표시합니다. (방금 추가했는데 바로 "놓침" 알림이 가는 일을 막기 위함)
- "놓침"은 약 시각 후 **60분**이 지나도록 복용 기록이 없을 때입니다. 이 값은 코드(`useCareStore.ts` 의 `medGraceMinutes`)에 고정되어 있고 화면에서 바꾸는 항목은 아직 없습니다.
- 처음에는 예시 약 4개(아모디핀 08:00, 관절 영양제 12:30, 메트포르민 18:30, 수면 보조제 21:30)가 들어 있습니다. 실제로 쓸 때는 지우고 본인 약으로 바꿉니다.

데이터 구조: `families/{코드}`(이름·약 목록·알림 기준·마지막 사용 시각), `families/{코드}/days/{날짜}`(기상·복용 기록), `families/{코드}/alerts/{id}`(알림 기록, 보호자 확인)

Firebase 를 새로 만들 때: 콘솔에서 웹 앱 추가 → Firestore 생성 → **Authentication > 익명** 켜기 → `firestore.rules` 내용을 규칙 탭에 게시 → 설정값을 `.env` 의 `VITE_FIREBASE_*` 에 입력.

### 휴대폰 알림 설정 (화면이 꺼져 있어도)

**11/23 설정 완료** (지금 동작 중). 아래는 Firebase 프로젝트를 새로 만들 때 다시 할 순서입니다. 모두 **무료**(Spark 요금제)입니다.

1. **웹 푸시 공개 키** — Firebase 콘솔 → ⚙ 프로젝트 설정 → **클라우드 메시징** → 웹 구성 → 웹 푸시 인증서 → **키 쌍 생성** → 공개 키를 `src/shared/api/push.ts` 의 `TEAM_VAPID_KEY` 에 넣습니다. (공개 키라 코드에 넣어도 됩니다)
2. **서비스 계정 키 (비밀)** — 프로젝트 설정 → **서비스 계정** → 새 비공개 키 생성 → 받은 JSON 파일 **내용 전체**를 Vercel → Settings → Environment Variables 에 `FIREBASE_SERVICE_ACCOUNT` 로 등록. ⚠️ 이 파일은 Git·채팅에 올리지 않습니다.
3. **CRON_SECRET** — 아무 긴 문자열을 하나 정해 Vercel 환경 변수 `CRON_SECRET` 과 GitHub → Settings → Secrets and variables → Actions 의 `CRON_SECRET` 에 **같은 값**으로 등록.
4. Vercel 에서 **Redeploy** (환경 변수는 다시 배포해야 적용).
5. **cron-job.org** (10분 간격): 가입 → CREATE CRONJOB → URL `https://senior-welfare-web.vercel.app/api/check`, Every 10 minutes, ADVANCED 탭 Headers 에 `Authorization` = `Bearer <CRON_SECRET>`, Time zone `Asia/Seoul` → TEST RUN 에서 200 OK 확인 → NOTIFICATIONS 에서 실패 2번 시 메일. (GitHub 무료 예약은 약 1시간 간격이라 예비로만 씀)
6. 확인: GitHub → Actions → **care-check** → Run workflow → 로그에 `{"families":…}` 가 나오면 성공. 휴대폰에서 '휴대폰 알림 받기'를 누르면 "늘봄을 닫아 두거나 화면이 꺼져 있어도 알림이 와요"가 표시됩니다.

동작: 어르신 앱이 긴급 요청·미확인 알림을 만들면 `/api/notify` 가 보호자 기기로 바로 보냅니다. 앱이 모두 닫혀 있으면 cron-job.org 가 10분마다(예비로 GitHub Actions) `/api/check` 를 불러 기상·복약 미확인을 보호자에게, 약 시간을 어르신에게 보냅니다. (같은 알림은 한 번만, GitHub 사정으로 몇 분 늦을 수 있음) 어르신이 '일어났어요'·'먹었어요'를 누르면 `/api/notify-checkin` 이 서버에 저장된 기록을 확인하고 보호자 기기로 "일어나셨어요 / 약을 드셨어요"를 보냅니다. (같은 날 같은 항목은 한 번만) 서버는 보낸 기기 수와 실패 이유를 로그로 남깁니다.

## 9. 알려진 한계

- 휴대폰 알림이 꺼져 있거나 무음·방해금지 모드면 알림을 놓칠 수 있습니다. 폰이 꺼지거나 인터넷이 끊기면 아무도 모르므로, '앱이 며칠 열리지 않으면 복지사가 전화' 같은 대비책이 필요합니다. (복지사 요약의 P5 연락 공백이 그 시작)
- 앱이 모두 닫혀 있을 때의 확인은 **10분 간격**(cron-job.org)이라, '약 드실 시간' 안내와 미확인 알림이 최대 10분 늦을 수 있습니다. cron-job.org 가 멈추면 GitHub Actions(약 1시간 간격)가 예비로 돕니다.
- 약은 **매일 같은 시간**으로만 설정할 수 있습니다. 요일별 복용과 약마다 다른 놓침 기준(현재 60분 고정)은 아직 없습니다.
- 가족 코드(6자리)를 아는 사람은 기록을 볼 수 있습니다. 프로토타입 수준의 보호이며, 서비스 전에는 계정 인증과 역할별 규칙이 필요합니다.
- `VITE_AUTH_MODE=firebase` 로 바꾸기 전까지 계정은 시연용이라 보안이 없습니다. (전환 방법: [계정 로그인으로 전환하기](#계정-로그인으로-전환하기)) 시연용 모드의 복지사 화면은 어르신 1명 고정입니다.
- 아이폰은 홈 화면에 추가한 앱에서만 알림을 받을 수 있습니다. (iOS 16.4 이상) 진동 세기 구분은 안드로이드에서만 됩니다.
- 보호자가 여러 어르신(최대 4명)을 보는 기능은 지금(시연용 계정 모드)만 됩니다. 계정 로그인 모드의 역할별 규칙은 보호자 1명당 어르신 1명이라, 켜기 전에 규칙을 고쳐야 합니다.
- 보호자가 지운 알림은 그 기기에만 저장됩니다. 폰과 컴퓨터를 함께 쓰면 각각 지워야 합니다.
- 서비스 워커·설치는 HTTPS(또는 localhost)에서만 동작합니다. `npm run dev` 에서는 꺼져 있습니다.

## 10. 폴더 구조

기능(feature) 단위로 나누고, 한 사람이 한 기능 폴더를 맡습니다. 자세한 규칙은 [CONTRIBUTING.md](CONTRIBUTING.md)를 보세요.

```
src/
  app/        앱 진입점: App(라우트), providers
  features/
    auth/       로그인(시연용 계정), 사용자 역할 스토어
    care/       안부·복약, 보호자 화면, Firebase 동기화, 알림
    dashboard/  홈 대시보드, 내 정보
    worker/     복지사 화면
  shared/     두 곳 이상에서 쓰는 것: ui, layout, hooks, api(firebase·push), store, lib
api/          Vercel 서버 함수(notify, notify-checkin, check)와 시험
scripts/      seed-accounts.mjs (Firebase 계정·역할·담당 배정 만들기), 아이콘 원본
firestore-tests/  Firestore 역할별 규칙 시험 (에뮬레이터)
public/       PWA 아이콘, 푸시용 서비스 워커
docs/         role-interfaces.md (역할별 인터페이스 전체 설계)
firestore.rules        현재 게시된 임시 규칙 (익명 로그인 + 가족 코드)
firestore.roles.rules  역할별 규칙 (계정 로그인으로 전환할 때 게시)
firebase.json          에뮬레이터 설정 (규칙 시험용)
```
