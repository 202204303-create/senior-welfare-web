# 늘봄 역할별 인터페이스 설계 (통합본)

> 대상: 어르신(elder), 보호자(guardian), 복지사(worker)
> 기준: 저장소 `202204303-create/senior-welfare-web` (main) 현재 코드
> 특히 **복지사 화면**은 담당 어르신이 많은 상황을 기준으로 자세히 설계했습니다.

---

## 0. 공통 원칙

### 0.1 역할별 목적

| 역할   | 핵심 질문                                   | 주요 행동                           | 정보 밀도 |
| ------ | ------------------------------------------- | ----------------------------------- | --------- |
| 어르신 | "오늘 뭘 해야 하지?"                        | 일어났어요, 약 체크, 긴급 요청      | 매우 낮음 |
| 보호자 | "오늘 괜찮은가? 지금 연락해야 하나?"        | 상태 확인, 이상 알림 확인, 전화     | 중간      |
| 복지사 | "오늘 누구를 먼저 챙기고, 무엇을 처리했나?" | 우선순위 확인, 빠른 처리, 상담 기록 | 높음      |

### 0.2 한 가지 데이터, 세 가지 화면

- 데이터는 Firestore `families/{code}`에 한 번만 저장합니다.
- 화면은 역할마다 따로 만듭니다. 데이터를 복사해 두 번 저장하지 않습니다.
- 공통 로직(기록 저장, 상태 계산, 알림 기록)은 `features/care/`에 두고, 화면이 가져다 씁니다.

### 0.3 현재 라우팅 (구현됨)

`src/app/App.tsx` 기준입니다.

| 경로        | 화면                 | 접근 역할 |
| ----------- | -------------------- | --------- |
| `/login`    | `LoginPage`          | 모두      |
| `/`         | `DashboardPage` (홈) | elder     |
| `/care`     | `CarePage` (약)      | elder     |
| `/alerts`   | `AlertsPage` (알림)  | elder     |
| `/my`       | `MyPage` (내 정보)   | elder     |
| `/guardian` | `GuardianPage`       | guardian  |
| `/worker`   | `WorkerPage`         | worker    |

- `RequireAuth`가 로그인 여부를 확인하고, 역할이 맞지 않으면 `homePathOf(role)`로 보냅니다.

### 0.4 현재 데이터 구조

```
families/{code}                 ← 6자리 가족 코드 (어르신 한 명당 하나)
  ├─ (문서 필드)                 ← FamilyInfo: 이름, 보호자 정보 등
  ├─ days/{YYYY-MM-DD}          ← DayDoc: 기상 시각, 복용 완료 목록
  ├─ alerts/{alertId}           ← 알림 기록 (최신 30개 조회)
  └─ pushTokens/{hash}          ← 보호자 기기 푸시 토큰
```

| 파일                              | 역할                                                                                                                   |
| --------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| `src/features/care/api/family.ts` | `saveFamilyInfo`, `saveDayRecord`, `saveAlert`, `saveHeartbeat`, `ackAlert`, `watchFamily`, `watchDays`, `watchAlerts` |
| `api/notify-checkin.ts`           | 어르신이 '일어났어요/먹었어요' 누르면 보호자에게 휴대폰 알림                                                           |
| `api/notify.ts`                   | 일반 알림 발송                                                                                                         |
| `api/check.ts`                    | 정기 확인 (기상·복약 미확인 점검, **확인 필요**)                                                                       |

## 1. 어르신 인터페이스

### 1.1 목표

- 할 일을 **한 번에 하나**만 보여 줍니다.
- 메뉴는 최소로 둡니다.
- "보호자께 전달했어요"처럼 안심시키는 문구를 씁니다.

### 1.2 화면 구성

| 화면    | 경로      | 핵심 요소                                                      |
| ------- | --------- | -------------------------------------------------------------- |
| 홈      | `/`       | 큰 "일어났어요" 버튼, 오늘 상태 한 줄, 긴급 요청 버튼          |
| 약      | `/care`   | 시간대별 약 목록(아침, 점심, 저녁, 취침 전), 체크 버튼, 진행률 |
| 알림    | `/alerts` | 보낸 알림 기록, 안심 문구                                      |
| 내 정보 | `/my`     | 프로필, 보호자 정보, 글자 크기                                 |

하단 메뉴(`AppLayout.tsx`의 `NAV`)는 홈, 약, 알림, 내 정보 네 개입니다.

### 1.3 상태 표현 규칙

| 상태              | 표시      | 글자 뱃지 |
| ----------------- | --------- | --------- |
| 복용 완료         | 초록 카드 | "복용함"  |
| 예정              | 기본 카드 | "예정"    |
| 지금 복용 시간    | 강조 카드 | "지금"    |
| 시간 지남, 미복용 | 주황 카드 | "놓침"    |

- 색만으로 구분하지 않습니다. 글자를 함께 씁니다.
- 상태 계산은 `getMedStatus`(`useCareWatcher.ts`)를 그대로 씁니다.

### 1.4 데이터 흐름

```
[버튼 클릭]
  → useCareStore (화면에 즉시 반영, 기기에 저장)
  → saveDayRecord (families/{code}/days/{날짜})
  → POST /api/notify-checkin (보호자에게 알림)
  → 토스트 "보호자께 전달했어요"
```

- 로컬 상태를 먼저 바꾸고 서버 저장은 뒤에서 합니다. 버튼이 바로 반응하게 합니다.
- 저장 실패 시 `ErrorState`와 "다시 시도" 버튼을 보여 줍니다.

### 1.5 알림

- 복약 시간 알림: `useCareReminder.ts`가 화면이 열려 있을 때 띄웁니다.
- 어르신에게 푸시를 보내는 것은 기본값에서 뺍니다. (알림 피로 방지)

### 1.6 접근성 체크리스트

- 기본 글자 18px 이상, 큰 글씨 옵션 20·22px
- 터치 영역 48px 이상
- 긴급 요청 버튼은 홈에 고정
- 아이콘만 있는 버튼에는 `aria-label` 필수

### 1.7 남은 작업

- [ ] 홈을 "한 가지 행동" 중심으로 재배치 (아침 전·후 상태에 따라 버튼 교체)
- [ ] 긴급 요청 확인 단계 (실수 방지: 길게 누르기 또는 확인 대화상자)
- [ ] `/alerts` 문구를 "보호자께 전달된 기록"으로 정리

## 2. 보호자 인터페이스

### 2.1 목표

- 첫 화면에서 **"오늘 괜찮은가?"**에 바로 답합니다.
- 이상이 있으면 맨 위에 띄우고, **전화 걸기**까지 한 번에 가게 합니다.

### 2.2 화면 구성 (`GuardianPage`, `/guardian`)

| 영역      | 내용                                                              |
| --------- | ----------------------------------------------------------------- |
| 상단 요약 | "오늘 괜찮아요" 또는 "확인 필요"                                  |
| 이상 카드 | 미확인 기상, 놓친 약, 긴급 요청. 카드마다 "확인했어요", 전화 버튼 |
| 오늘 기록 | 기상 시각, 복약 체크 목록                                         |
| 최근 기록 | 날짜별 목록 (7일, 30일)                                           |
| 알림 기록 | `watchAlerts`로 받은 최근 알림                                    |
| 설정      | 푸시 허용 (`PushPermission`), 가족 코드                           |

### 2.3 현재 구현 상태

- 가족 코드는 `localStorage`(`neulbom-guardian-code`)에 저장합니다.
- 코드는 직접 입력하거나 URL 파라미터로 받습니다 (`useSearchParams`, `useShareGuardianLink`).
- 실시간 구독: `watchFamily`, `watchDays`, `watchAlerts`.
- 상태 판정: `findCareIssues` (`guardianIssues.ts`), 상태 색상: `STATUS_STYLE` (`status.ts`).

### 2.4 알림

- 휴대폰 푸시가 핵심입니다. 앱이 닫혀 있어도 와야 합니다.
- 경로: 어르신 행동 → `api/notify-checkin.ts` → FCM → 보호자 기기.
- 토큰 등록: `push.ts` → `families/{code}/pushTokens`.

### 2.5 이상 카드 설계

```
┌────────────────────────────────────────┐
│ ⚠ 오늘 아침 기상 확인이 안 됐어요        │  ← 글자 + 아이콘
│ 10:00 기준 · 15분 전                    │
│ [전화 걸기]                [확인했어요]   │
└────────────────────────────────────────┘
```

- "확인했어요"는 `ackAlert(code, alertId, ackBy)`로 기록합니다. `ackBy`에는 보호자 이름을 넣습니다.

### 2.6 남은 작업

- [ ] 보호자 계정 로그인 (현재는 가족 코드 입력) → Firebase 이메일 로그인
- [ ] 어르신 여러 명 연결 시 선택 화면
- [ ] 연락처 버튼을 `tel:` 링크로
- [ ] 푸시가 꺼져 있으면 상단에 경고

## 3. 복지사 인터페이스 (상세)

### 3.0 설계 전제

- 복지사 한 명이 **수십 명**을 담당할 수 있습니다. 모든 사람을 똑같이 보여 주면 중요한 사람을 놓칩니다.
- 그래서 화면은 **"누구를 먼저 볼지 → 어떻게 빨리 처리할지 → 각 사람의 기록을 어떻게 볼지"** 세 단계로 나눕니다.
- 복지사의 하루는 대략 이렇게 흐릅니다.

```
출근 → [오늘 큐] 긴급·미확인부터 처리 → 통화·방문 → 기록 작성
     → [명단] 나머지 상태 점검 → 퇴근 전 [미처리 점검]
```

---

### 3.1 무엇을 먼저 봐야 하는가? → "오늘 큐" (홈 화면)

복지사 홈은 명단이 아니라 **처리할 일의 줄(큐)**입니다. 어르신 단위가 아니라 **이슈 단위로 한 줄씩** 보여 줍니다.

#### 우선순위 등급

| 등급                  | 조건                                   | 색 + 글자             | 기대 처리 시간  |
| --------------------- | -------------------------------------- | --------------------- | --------------- |
| **P1 긴급**           | 어르신이 긴급 요청을 누름              | 빨강 "긴급"           | 즉시 (5분 이내) |
| **P2 에스컬레이션**   | 보호자가 N분(예: 30분) 동안 확인 안 함 | 주황 "보호자 미확인"  | 1시간 이내      |
| **P3 기상 미확인**    | 기준 시각(예: 10시) 지나도 기상 없음   | 주황 "기상 미확인"    | 당일 오전       |
| **P4 복약 연속 놓침** | 같은 약을 2회 이상 연속 놓침           | 노랑 "복약 누락 반복" | 당일            |
| **P5 연락 공백**      | 마지막 처리 후 N일 경과 (예: 3일)      | 파랑 "연락 필요"      | 이번 주         |
| **P6 예정**           | 오늘 방문·통화 일정이 있음             | 회색 "오늘 예정"      | 일정 시각       |
| **P7 정상**           | 이슈 없음                              | 초록 "정상"           | 목록에서만 확인 |

#### 정렬 규칙 (설명 가능해야 함)

1. 등급이 높은 것이 위 (P1 → P7)
2. 같은 등급이면 **오래 기다린 것이 위** (이슈가 생긴 시각 기준)
3. 같은 어르신의 여러 이슈는 **한 카드로 묶음**

#### "왜 여기 있나?" 칩

각 줄에 이유를 칩으로 보여 줍니다. 복지사가 정렬 결과를 믿고 따라갈 수 있게 합니다.

```
┌──────────────────────────────────────────────────────────┐
│ 🔴 P1 긴급   김영수 (78세, 서울 중구)          10:42 · 8분째 │
│ [긴급 요청] [보호자 미확인 25분] [독거]                    │
│ [📞 어르신] [📞 보호자 딸]   [처리하기 ▸]                   │
└──────────────────────────────────────────────────────────┘
```

#### 화면 상단 요약 바

```
오늘 관리 12명 · 긴급 1 · 미확인 2 · 방문 예정 3 · 처리 완료 5/12
[████████░░░░░░] 42%
```

- 숫자 칩을 누르면 그 등급만 필터링됩니다.
- 진행률 바로 "오늘 끝났는지"를 한눈에 확인합니다.

### 3.2 어떻게 해야 빠르게 처리할 수 있는가?

#### (1) 원탭 처리 결과 버튼

이슈 카드에서 **한 번 누르면 결과가 기록**되도록 합니다. 메모를 쓰지 않아도 처리가 끝나야 합니다.

| 결과 버튼        | 기록되는 결과       | 처리 후 동작                       |
| ---------------- | ------------------- | ---------------------------------- |
| 통화 · 이상 없음 | `call_ok`           | 이슈 종결, 정상으로 전환           |
| 통화 · 받지 않음 | `call_no_answer`    | 이슈 유지, "재시도 예정" 시각 설정 |
| 방문 필요        | `visit_needed`      | 방문 일정 칸 열림                  |
| 보호자에게 전달  | `guardian_notified` | 이슈 유지, 보호자 응답 대기        |
| 기타 (메모 입력) | `other`             | 메모 필수                          |

- 결과를 고르면 **즉시 저장**하고, 카드에 "방금 · 통화 · 이상 없음"이 남습니다.
- 실수 방지: 저장 후 5초 동안 "되돌리기" 토스트를 띄웁니다.

#### (2) 연락은 한 탭으로

- 전화 버튼은 어르신과 보호자를 **둘 다** 보여 줍니다. 보호자 번호가 먼저 나오는 경우는 기본값으로 둡니다. (팀 결정 필요)
- 통화 버튼을 누르면 `tel:` 링크가 열리고, 복지사가 돌아오면 **"통화 결과 기록"** 시트가 자동으로 뜹니다.

#### (3) 템플릿 메모

자주 쓰는 문장을 칩으로 제공합니다. 탭 한 번이면 메모가 채워집니다.

- "통화 완료, 식사 잘 하심"
- "부재중, 30분 뒤 재시도"
- "복약 확인 요청함"
- "보호자와 통화, 방문 협의"
- "이상 없음, 다음 주 재확인"

템플릿은 `families/{code}/actions` 기록에 `templateId`로 함께 저장합니다. 나중에 같은 문장을 반복해서 쓸 때 통계가 됩니다.

#### (4) 일괄 처리 (정상 건만)

- 명단에서 체크박스로 여러 명을 고르고 **"정상 확인"**을 한 번에 처리할 수 있습니다.
- 단, **이슈가 있는 사람은 일괄 처리할 수 없습니다.** 이슈는 반드시 한 건씩 결과를 남기게 합니다.

#### (5) 알림 묶음 (알림 피로 방지)

- 같은 어르신의 같은 날 알림은 "김영수 · 오늘 알림 3건" 한 카드로 묶습니다.
- 펼치면 개별 알림과 시각이 보입니다.

#### (6) 키보드 단축키 (데스크톱)

| 키        | 동작                         |
| --------- | ---------------------------- |
| `J` / `K` | 다음 / 이전 이슈로 이동      |
| `Enter`   | 선택한 이슈 열기 (차트 화면) |
| `E`       | "통화 · 이상 없음"으로 처리  |
| `C`       | 통화 결과 기록 시트 열기     |
| `/`       | 이름 검색창으로 이동         |
| `?`       | 단축키 도움말                |

#### (7) 자동 종결 규칙

- 보호자 확인 → 복지사 처리 완료 → 다음 기록에서 정상이 확인되면 이슈는 **자동으로 닫힙니다.**
- 닫힌 이슈는 "완료" 탭에 남아 나중에 찾을 수 있습니다.

### 3.3 각 고령자별 차트 (케이스 화면)

#### 차트 화면 전체 구조

```
┌───────────────────────────────────────────────────────┐
│ ← 목록   김영수 · 78세 · 독거 · 서울 중구               │ ← 고정 헤더
│ 상태 [관찰]   마지막 연락 오늘 10:42                     │
│ 📞 어르신 010-xxxx   📞 보호자(딸) 010-xxxx            │
│ ⚠ 특이사항: 혈압약 복용 주의 · 청력 약함 (크게 말하기)   │ ← 고정 메모
├───────────────────────────────────────────────────────┤
│ [개요] [타임라인] [복약] [상담 기록] [특이사항]          │ ← 탭
├───────────────────────────────────────────────────────┤
│ (선택한 탭의 내용)                                      │
└───────────────────────────────────────────────────────┘
```

#### 탭별 내용

| 탭            | 내용                                                           | 주요 기능                                    |
| ------------- | -------------------------------------------------------------- | -------------------------------------------- |
| **개요**      | 이번 주 요약: 기상 준수율, 복약 준수율, 처리 건수, 마지막 통화 | 7일 막대 그래프 1개만 (복잡하게 만들지 않기) |
| **타임라인**  | 알림, 기상, 복약, 처리 기록을 **시간순**으로 합친 목록         | 종류별 필터 칩 (알림 / 기록 / 상담)          |
| **복약**      | 약 목록, 최근 14일 복용 표                                     | 놓친 칸만 색으로 표시 + 글자                 |
| **상담 기록** | 작성 폼 + 과거 기록 목록                                       | 템플릿 칩, 다음 행동, 다음 일정              |
| **특이사항**  | 고정 메모 (주의 사항, 가족 사정, 좋아하는 것)                  | 고정(📌) 항목은 모든 탭 헤더에 보임          |

#### 상담 기록 작성 폼 (빠르게)

```
[템플릿 선택 ▾]  [통화 · 이상 없음] [식사 잘 하심] [약 잘 드심] ...
메모 (선택): ________________________________
다음 행동:  ( ) 없음  ( ) 재통화  ( ) 방문  ( ) 보호자 협의
다음 일정: [2026-11-27 ▾] [10:00 ▾]
                                     [저장]
```

- 저장 후에는 **수정할 수 없습니다.** 틀렸다면 "정정 기록"을 새로 추가합니다. (감사 기록 보존)
- 기록에는 작성자, 작성 시각이 자동으로 들어갑니다.

#### 차트 데이터 설계 (읽기 비용 줄이기)

문제: 명단 50명 × 날짜별 기록을 모두 구독하면 읽기 비용과 로딩이 커집니다.
해결: **요약 문서**를 서버가 미리 만들어 둡니다.

```
families/{code}/summary        ← 서버 함수가 기록이 생길 때마다 갱신
  ├─ todayWake: 시각 | null
  ├─ todayMedDone: 2, todayMedTotal: 4
  ├─ openIssues: [{type, grade, since}]   ← 열린 이슈 목록
  ├─ openCount: 2
  ├─ highestGrade: "P2"
  ├─ lastContactAt: 시각
  ├─ status: "정상" | "관찰" | "위험"
  └─ updatedAt: 시각
```

- 명단과 오늘 큐는 **summary만** 읽습니다.
- 차트의 과거 기록은 **그 어르신을 열었을 때만** 가져옵니다. (지연 로딩)

#### 특이사항 (고정 메모) 데이터

```
families/{code}/notes/{noteId}
  ├─ text, pinned(true/false), category("의료" | "생활" | "연락"), createdBy, createdAt
```

### 3.4 오늘 관리해야 할 사람은 누구인가? → "오늘 관리 대상"

#### 자동으로 들어가는 조건 (하나라도 해당하면 오늘 목록에 포함)

1. 열린 이슈(P1~P5)가 하나라도 있음
2. 오늘 방문·통화 일정이 있음
3. 마지막 연락 후 N일 이상 경과 (기본 3일)
4. 상태가 "위험" 또는 "관찰"로 표시됨
5. 복지사가 직접 **"오늘 챙기기"**로 핀 고정함

#### 목록 화면

```
오늘 관리 대상  12명                                   [필터 ▾] [정렬 ▾]
──────────────────────────────────────────────────────────────────
☐ 🔴 김영수   긴급 요청 · 8분째        다음: 10:30 방문    [처리]
☐ 🟠 이순자   보호자 미확인 · 25분째    마지막 통화 어제    [처리]
☐ 🟠 박정례   기상 미확인 (10:00)       마지막 통화 3일 전  [처리]
☐ 🔵 최민수   연락 필요 · 4일째         다음: 14:00 통화    [처리]
☐ 🟢 정미경   정상 · 약 4/4             마지막 통화 오늘    [보기]
```

- 기본 정렬: 등급 → 기다린 시간
- 필터: 등급별, 동별, 상태별, "보호자 없음"
- 저장된 보기(saved view): "내 방문 예정", "이번 주 연락 필요" 같은 조합을 저장

#### 퇴근 전 점검 (자동 체크리스트)

```
퇴근 전 확인 (남은 것 3건)
☐ 김영수 · 긴급 요청 미처리
☐ 이순자 · 보호자 미확인 (내일로 넘기면 자동 에스컬레이션)
☐ 박정례 · 방문 기록 없음
```

- 남은 항목이 없어야 "오늘 완료"가 됩니다.
- 미처리 항목은 다음 날 오늘 큐 맨 위로 자동 이월합니다.

### 3.5 전체 명단 (담당 전체 보기)

오늘 큐와 별개로, **담당 전체를 한눈에 보는 목록**입니다.

| 열          | 내용                           |
| ----------- | ------------------------------ |
| 상태        | 정상 / 관찰 / 위험 (색 + 글자) |
| 이름        | 누르면 차트                    |
| 나이·거주   | 간단히                         |
| 마지막 통화 | "오늘 10:42", "3일 전"         |
| 오늘 기상   | 시각 또는 "미확인"             |
| 오늘 복약   | "2/4"                          |
| 열린 이슈   | 개수                           |
| 다음 일정   | 방문·통화 시각                 |
| 태그        | 독거, 보호자 없음, 고위험 등   |

- 검색: 이름, 동, 태그
- 모바일에서는 표 대신 카드 목록으로 바꿉니다.
- 행이 많으면 가상 스크롤(화면에 보이는 행만 그리기)을 씁니다.

### 3.6 이슈 상태 흐름

```
[새 알림]
   │
   ▼
[보호자 대기] ── 보호자 확인 ──▶ [보호자 확인됨] ──▶ 복지사 처리 불필요 → 자동 종결
   │
   │ (N분 경과, 미확인)
   ▼
[복지사 대상 P2] ── 복지사 결과 기록 ──▶ [처리 중]
                                          │
                                          ▼
                                   [처리 완료] ── 다음 기록에서 정상 ──▶ 자동 종결
                                          │
                                          └─ 재시도 예정 ──▶ [처리 중] (재등장)
```

- 상태 변경은 모두 `actions`에 기록합니다. 누가, 언제, 어떤 결과인지 남깁니다.

### 3.7 데이터 모델 (복지사 기능 추가분)

```
workers/{workerUid}
  ├─ name, role: "worker"
  └─ assignments/{code}
        ├─ displayName: "김영수"         ← 복지사가 보기 편한 이름
        ├─ dong: "중구"
        ├─ tags: ["독거", "고위험"]
        ├─ pinnedToday: true | false     ← "오늘 챙기기" 핀
        └─ addedAt

families/{code}/actions/{actionId}       ← 처리·상담 기록 (추가만 가능)
  ├─ at, by(uid), byName
  ├─ type: "이슈처리" | "상담" | "정정"
  ├─ result: "call_ok" | "call_no_answer" | "visit_needed" | "guardian_notified" | "other"
  ├─ templateId (선택)
  ├─ alertId (선택)
  ├─ note (선택)
  ├─ nextAction: "none" | "recall" | "visit" | "guardian"
  └─ followUpAt (선택)

families/{code}/summary                  ← 서버가 갱신 (3.3 참고)
families/{code}/notes/{noteId}           ← 특이사항 (고정 메모)
```

- `assignments`는 `workers/{uid}` 하위에 둬서, 복지사 한 명이 담당 목록을 한 번에 읽을 수 있게 합니다.
- Firestore의 `in` 조건은 한 번에 30개까지라서, 담당이 많으면 summary를 나눠서 읽습니다. (확인 필요: 실제 담당 인원 상한)

### 3.8 보안 규칙 (복지사)

```
// 복지사: 담당 배정된 가족만 읽기, 처리 기록은 추가만
match /families/{code} {
  allow read: if request.auth != null
    && exists(/databases/$(database)/documents/workers/$(request.auth.uid)/assignments/$(code));
  match /actions/{id} {
    allow read: if <위와 같은 담당 조건>;
    allow create: if <위와 같은 담당 조건>
      && request.resource.data.by == request.auth.uid;
    allow update, delete: if false;   // 수정·삭제 불가
  }
}
```

- 실제 규칙은 역할 판정(보호자 / 복지사 / 어르신)을 함께 넣어 작성합니다. 위는 복지사 부분만 보여 주는 예시입니다.
- 복지사 계정은 **관리자가 담당을 배정**하기 전에는 아무 가족도 볼 수 없어야 합니다.

### 3.9 에스컬레이션 (보호자 → 복지사)

1. 알림 발생 → 보호자에게 푸시
2. N분(예: 30분) 안에 보호자가 "확인" 안 함
3. 복지사 오늘 큐에 **P2**로 올리고 복지사에게 푸시
4. 복지사가 결과를 기록하면 종료

- 구현 위치: 정기 확인 함수(`api/check.ts`)에 "미확인 경과 시간" 조건을 추가하는 방식이 적합해 보입니다. (확인 필요)

## 4. 공통 구현 영역

### 4.1 인증과 역할

- 현재: 시연용 계정(`demoAccounts.ts`)이 아이디와 비밀번호를 코드에 둡니다. 보안이 아닙니다.
- 목표: Firebase 이메일 로그인 + 사용자 문서에 `role` 저장. 역할 확인은 Firestore 규칙에서도 한 번 더 합니다.

### 4.2 권한 규칙 요약

| 대상   | 읽기             | 쓰기                                            |
| ------ | ---------------- | ----------------------------------------------- |
| 어르신 | 자기 가족 문서   | 자기 날짜 기록, 알림 생성                       |
| 보호자 | 연결된 가족 문서 | 알림 확인(`ackBy`), 가족 정보 일부              |
| 복지사 | 배정된 가족 문서 | 알림 확인, 처리·상담 기록 추가 (수정·삭제 불가) |

현재 `firestore.rules`는 "가족 코드 6자리를 아는 로그인 사용자"만 허용합니다. 위 표대로 역할별로 나눠야 합니다.

### 4.3 알림 정책 요약

| 대상   | 채널                     | 시점                            |
| ------ | ------------------------ | ------------------------------- |
| 보호자 | 휴대폰 푸시, 화면 토스트 | 어르신 행동 직후, 미확인 시     |
| 복지사 | 휴대폰 푸시              | 긴급 요청, 에스컬레이션         |
| 어르신 | 화면 안 알림만           | 복약 시간 (화면이 열려 있을 때) |

### 4.4 공통 UI 컴포넌트

- `shared/ui`의 `BigButton`, `InfoCard`, `EmptyState`, `ErrorState`, `LoadingList`, `StatusNote`, `NoticeStack`를 세 역할이 함께 씁니다.
- 역할별 컴포넌트는 `features/<역할>/components/`에 둡니다.
- 상태 색상은 `features/care/lib/status.ts`의 `STATUS_STYLE`을 공유합니다.

## 8. 완료 기준 (Definition of Done)

- [ ] 세 역할이 로그인 후 각자의 첫 화면으로 이동한다
- [ ] 역할이 맞지 않는 주소로 접근하면 막히고 안내가 나온다
- [ ] 보호자는 자기 가족 기록만 본다 (규칙 테스트로 확인)
- [ ] 복지사는 배정된 가족만 보고, 처리 기록은 수정·삭제할 수 없다
- [ ] 복지사 오늘 큐가 우선순위 규칙대로 정렬된다 (테스트 케이스 포함)
- [ ] 원탭 처리 후 3초 안에 카드 상태가 바뀐다
- [ ] 차트 화면에서 과거 7일 기록이 타임라인에 시간순으로 보인다
- [ ] 알림이 보호자와 복지사에게 앱이 닫혀 있어도 도착한다
- [ ] 세 화면 모두 로딩, 오류, 빈 결과 상태가 있다
- [ ] 어르신 화면이 접근성 체크리스트(1.6)를 통과한다
